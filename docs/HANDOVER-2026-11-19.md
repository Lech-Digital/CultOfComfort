## How to pick it up on a fresh machine

- **.NET.** The simulation tests and the sandbox target .NET 8; with only .NET 10 installed, prefix
  `DOTNET_ROLL_FORWARD=Major`:
  - `DOTNET_ROLL_FORWARD=Major dotnet test tests/CultOfComfort.Simulation.Tests`
  - `dotnet test tests/CultOfComfort.Server.Tests`
  - The pace bot: `DOTNET_ROLL_FORWARD=Major dotnet run --project tools/CultOfComfort.Sandbox -c Release -- pace errands --hours 30 --fight active|idle`
  - Build the simulation (`dotnet build src/CultOfComfort.Simulation -c Release`) before the Unity tests: it copies
    the DLL into `Assets/Plugins` (gitignored).
- **Unity 6000.3.26f1.** `unity test client/CultOfComfort.Unity --mode EditMode|PlayMode`; wrap it in
  `systemd-run --user --scope -p MemoryMax=6G` to keep the RAM in check.
  - Screen captures are explicit PlayMode tests: `--filter NightCapture_…|HudCapture`.
  - The store shots: `--filter NightCapture_Store_WritesShots`, then
    `CHROME=/usr/bin/google-chrome node store-assets/_src/build.mjs`.
- **Blender 4.5.16 LTS** at `~/Applications/blender-4.5.16-linux-x64/blender`:
  - `BLENDER=… ./art/build.sh <model>|--all|--icons|--test`
- **A local server for playtests:**
  ```sh
  cd src/CultOfComfort.Server
  ASPNETCORE_ENVIRONMENT=Development ConnectionStrings__Db="Data Source=/tmp/coc.db" \
    dotnet run --no-launch-profile --urls http://0.0.0.0:5080
  ```
- **The emulator playtest:**
  1. Build the APK: `BuildScripts.BuildAndroid -emulator` (x86_64), then revert `ProjectSettings.asset`.
  2. Boot the emulator: `~/android-sdk/emulator/emulator -avd coc-play -memory 3072 -cores 2 -no-window -no-audio -no-snapshot -no-boot-anim -feature -Vulkan -gpu host`.
  3. Install the APK with the network off (`adb shell svc wifi disable; svc data disable`).
  4. Launch it once so it unpacks, then force-stop it.
  5. Remove `village-cache.json` from `/storage/emulated/0/Android/data/com.lechdigital.cultofcomfort/files/`.
  6. Push a `server.url` file with `http://10.0.2.2:5080` into that folder. Development builds only read it.
  7. Turn the network back on and launch.

  Close with `adb emu kill`.

  **After the reset (2026-11-19 14:00), with nobody logged into the desktop:**
  - The emulator won't start ("x86_64 emulation currently requires hardware acceleration"). `/dev/kvm` is opened only
    to the user logged into the desktop, and the GPU mode needs a display. Either log into the desktop, or run
    `sudo usermod -aG kvm andrzej` and log in again.
  - Unity batch builds need `-nographics` (no X display). PlayMode screen captures need the desktop session. A reinstall over leftover external files fails with a false "not enough storage";
  `adb shell pm clear com.lechdigital.cultofcomfort` fixes it on the emulator. That false error is in the backlog.
